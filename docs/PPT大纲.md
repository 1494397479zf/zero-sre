## P1 封面

- 项目名：ZeroDBA：零人工运维数据库多Agent系统
- 一句话命题：**敢让 AI 动生产数据库——用验证通道、分级门禁、JIT 权限三重保险回答"敢"**
- 赛道：Agent Infra · 方向一 零人工运维 · 高校学生团队署名（队名自定）

## P2 问题与场景 【场景价值】

- 数据库运维"人盯着才转"：告警人查、慢SQL人诊、变更人批
- 为什么数据库最难自动化：有状态、难回滚、根因链深（慢SQL→锁等待→连接池→应用超时）
- 托管场景放大痛点：规模要求全自动，爆炸半径要求极谨慎
- 点题：全场直觉都是"不敢"，我们正面回答

## P3 核心方案总览 【场景价值+协同】

- 闭环图（方案设计 4.4 总览图）
- 三类任务入口：告警/巡检/工单
- 一句话架构：3 Agent + 2 流水线，确定性内核 + 判断点薄 Agent
- 人只在门禁处"点头"

## P4 架构与 AgentTeams 映射 【多Agent协同】

- 3 Agent 职责表：Manager（分级派单裁决）/ 诊断验证（六域+证据闸门）/ 变更（选型门禁执行）
- 2 流水线：巡检（主动发现）、知识（沉淀飞轮）
- **AgentTeams 映射表**（赛道必查）：角色编排→CRD、任务拆解→三级委派、上下文→MinIO、状态追踪→Reconcile+心跳、审批→Human+Room、审计→Matrix 持久化

## P5 任务拆解与上下文传递 【多Agent协同】

- 主干流水线图（4.5 图，含 P0 分叉/历史命中/快照三条分支）
- 域插件表（新增域只加一行不改主干）
- 交接契约：结构化 JSON + IM 只传指针；大产物落 MinIO
- 脱敏边界：进 LLM 上下文前先脱敏

## P6 诊断引擎 【多Agent协同+Skill】

- 六域采集 + seed calls（LLM 出场前先拿免费证据）
- 假设-验证循环 ≤2 轮求伪；变更时间线第一轮强制对齐
- 量化护栏表（工具上限/循环上限/停滞熔断/重复缓存/上下文预算/噪声短路）
- 结构化结论：已验证/未验证声明分开 + 置信度

## P7 快照验证通道 ★创新 【工程落地】

- 不重建近似环境，直接备份拉起"生产的副本"——零失真
- HypoPG What-If（不建索引比对 cost）+ dry-run + gdb 抓栈
- 生产零写入零 attach；TTL 自动销毁
- 金句："先在生产的副本上跑一遍，再动生产"

## P8 执行与安全体系 【工程落地】

- 分级门禁图（4.8 图）：L0-L3，自动化随风险递减
- 双层 JIT：Higress（工具路由）× STS（单次动作凭证，到期失效）
- P0 紧急通道：先止血后追因 + 保命SQL保护 + TTL + 一键解除
- 审计三层：云助手记录 × ActionTrail × Matrix 消息

## P9 异常分支与风险控制 【工程落地】

- 异常表精选 6 条：取数失效降级人工 / 验证通道不可用禁生产 attach / LLM 失败保留证据 / 止血未生效禁盲目升级 / 回滚失败冻结实例
- 灰度纪律：影子运行对齐 → L1 先行 → L2 按实例放量 → L3 永不自动
- 宁可漏配不可误配
