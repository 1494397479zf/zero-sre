# 基建映射改造方案

> 底稿：《无人值守的数据库运维Agent（zero-SreAgent）》（内部设想，未落地）
> 目标：将底稿中的内网（阿里控股平台技术）基建依赖，逐一映射为阿里云公网能力，形成可参赛、可在 ECS 自建库环境真实跑通的方案
> 环境设定：阿里云 ECS 上自建 PG/MySQL 三节点；公网账号；无内网平台可用
> 整理日期：2026-08-10
> 状态：设计稿，各项标注可行性与待验证项

## 1. 改造原则

1. **方法论不动，基建替换**：底稿的核心设计（确定性内核+薄判断、阶段化岗位、快照 dry-run、L0-L3 门禁、实例知识飞轮）全部保留，只替换依赖的底层设施
2. **能用官方能力不自建**：优先 DAS/CMS/SLS/云助手官方 API，自建只补官方覆盖不到的缺口
3. **每个替代明确降级路径**：某能力验证不通过时，方案怎么退化而不崩塌
4. **初赛可裁剪**：每项标注"初赛 Demo 最小形态"，保证 8/16 前可交付

## 3. 六大替代模块设计

### 模块 A：观测体系（替代 Sunfire + 监控平台 MCP）

- **主机指标**：CMS 自动采集（acs_ecs_dashboard），DescribeMetricList 查询
- **数据库进程级指标**：自建指标采集器（定时脚本，经云助手部署到 ECS），采集 pg_stat_* / SHOW GLOBAL STATUS 关键项，双写 CMS 自定义监控（挂告警规则）+ SLS（灵活分析）
- **日志**：LoongCollector 采集错误日志/慢日志/系统日志进 SLS
- **异常检测**：DAS 异常事件 API（ML 检测，四级紧急度）——⚠️ 对自建库生效性待验证，降级方案：CMS 自定义指标阈值告警
- **告警入口**：Manager 定时轮询 DAS GetAutonomousNotifyEventsInRange + CMS DescribeAlertLogList（初赛形态）；EventBridge 事件驱动（复赛进阶）

### 模块 B：诊断引擎（替代 SQL 优化引擎 + 六域采集）

- **六域框架保留**：metric/sql/session/event/change/statistics 全部保留；tddl 删除；kernel 保留（见模块 C 的 gdb 通道）
- **诊断 Skill 改造**：db-troubleshooting 的六步引擎、快速路径 FP-1~8、冲突消解优先级、派生指标公式**全部保留**，只把 `dbs`/Sunfire 工具调用替换为：CMS/SLS 查询 + DAS API + 云助手只读 SQL
- **SQL 优化能力降级方案**：底稿的 SQL 优化引擎（输出索引/改写建议）公网无等价物。替代：DAS GetSqlOptimizeAdvice（自动 SQL 优化建议，⚠️ 待验证自建库）+ LLM 薄判断层 + 规则库（L1-L4 规则沿用底稿设计）。**这是全方案最大的能力缺口，PPT 上要坦诚说明并给演进路线**
- **变更时间线对齐**（第一轮强制）：公网无统一变更记录平台——用云助手 DescribeInvocations（自身执行记录）+ 本地变更台账（知识库维护）替代，初赛可简化

### 模块 C：验证通道（替代快照 dry-run）★ 核心卖点保全

底稿设计：打一致性快照 → 拉起临时验证实例 → dry-run/gdb → TTL 销毁。公网 ECS 自建场景的实现：

- **拉起方式**：物理备份（pg_basebackup / xtrabackup）或 ECS 磁盘快照恢复到一台**临时验证 ECS**；逻辑方式可用 pg_dump/mysqldump（小库）
- **保真度**：数据/统计/参数/内核版本与生产一致（同一备份源），底稿"零失真"论点完全成立
- **重动作执行**：云助手在验证实例执行 gdb attach 抓栈、真实建索引、DDL 演练、SQL 改写试跑
- **What-If 索引验证**：PG 用 **HypoPG 扩展**（虚拟索引 + EXPLAIN 成本比对，不真实建索引）；MySQL 无等价扩展，用"验证实例上真实建索引 + CloudBench 回放比对"
- **流量回放**：DAS CloudBench（⚠️ 自建库支持待验证），降级方案：sysbench/自录流量回放脚本
- **TTL 销毁**：验证 Worker 定时任务到期释放临时 ECS（OpenAPI DeleteInstance），成本随用随付
- **安全边界不变**：生产实例零写入零 attach，gdb 只允许在验证实例

### 模块 D：执行与门禁（替代平台止血/工单通道）

- **L1 止血**：DAS 限流/kill 会话 API（首选，不依赖主机 Agent 存活度）；降级：云助手执行 SQL（实例夯死时两者都不可用 → 升级人工，与底稿异常分支一致）
- **TTL 模拟**：DAS 无原生 TTL——止血时由 Manager 注册定时撤销任务（到期自动调 Disable/解除），等效实现"限时止血"
- **L2 受控变更**：底稿走平台工单；公网替代 = **Matrix 房间审批（人点头）+ 云助手执行（DryRun 预检→Username 最小权限→ClientToken 幂等）**，工单语义由 AgentTeams 任务状态机承载
- **L3 高危**：永远人批准，Agent 只出方案——不变
- **白名单制**：不变，白名单落在 Skill 的工具定义层
- **执行审计**：云助手执行记录（30 天）+ ActionTrail（云 API）+ Matrix 消息，三层叠加超过底稿要求

### 模块 E：知识层（实例知识库 + 规则库）

- **存储**：PolarDB for PostgreSQL + pgvector——赛道推荐的 Agent 数据层，同时承载：实例画像、四元组（问题→根因→动作→效果）、向量检索、全局规则库、负样本库
- **种子规则**：初赛知识库为空会削弱"飞轮"演示——预置 db-troubleshooting 的规则库（rules/*.yaml 脱敏后）+ 团队历史案例脱敏样本作为种子
- **两级沉淀机制**（实例级记忆 + 全局规则）：不变

### 模块 F：协同底座（AgentTeams，零改造）

底稿 4.1 的映射全部成立且无需改造：Manager-Workers、Matrix 房间 HITL、MinIO 共享上下文、Higress 凭据隔离、多运行时混编、K8s CRD。唯一补充：凭据隔离从"平台认证凭据"具体化为 RAM/STS + Higress 双层 JIT（见 api-reference/sts.md）。

## 4. 关键取舍与降级矩阵

| 风险 | 触发条件 | 降级策略 |
|---|---|---|
| DAS API 对自建库不生效 | 待验证 #1-3 不通过 | 诊断全面走"云助手只读 SQL + SLS + 自建脚本"路线，DAS 降级为可选增强；方案叙事从"复用云自治能力"改为"自建诊断引擎"，工作量增加但可行性不受影响 |
| CloudBench 不支持自建库 | 待验证 #5 不通过 | 流量回放用 sysbench + 自录请求日志 |
| 快照拉起耗时过长 | 大库恢复超 Demo 时长 | Demo 用小库；PPT 说明生产形态用增量备份缩短窗口 |
| SQL 优化引擎缺口被评委挑战 | 决赛答辩 | 坦诚现状 + 演进路线（接入 DAS SQL 优化/自研 cost 模型），并强调验证通道的存在使"建议必须过真实验证"——比有优化引擎但无验证更可信 |
